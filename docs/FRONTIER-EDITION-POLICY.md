# Frontier edition and challenge-escalation policy

Status: preregistered operating policy; no live-model result is claimed.

## Why editions exist

A benchmark can be correct and still stop being informative. If every eligible
frontier-model cell passes every task in all five attempts, the result is a
useful ceiling finding for that exact edition. It is not permission to edit the
tasks after seeing the answers and report the harder replacement as though it
were the original test.

Gradia therefore keeps three different objects:

- **v1 — frozen evaluation anchor.** The original tasks, worlds, judges,
  scaffold and analysis remain immutable.
- **v1+ — disclosed development challenge set.** New conditions may be derived
  from observed ceiling or failure traces. It is useful for debugging and
  training, not an untouched confirmation set.
- **v2 — sealed held-out evaluation edition.** It tests the same declared
  capability construct in new worlds with new data, events and answers. Its
  task answers and final cells are not used to design v1+.

No edition overwrites another. Every report names the exact edition digest.

## v1 pre-run admission ruling

The current five-task v1 is admitted as a **calibration anchor**, not as a
guarantee that frontier models will fail. It contains one static control and
four dynamic tasks over four coupled cases, six versioned sources, global
exception capacity, authoritative and unverified messages, exact cutoff
boundaries, policy/capacity/document/condition changes, one restore and a
five-event chained condition. A valid answer must resolve the whole queue,
recompute case metrics, allocate a scarce exception globally, await the cutoff,
re-read every changed source, cite actual source-read evidence and bind the
terminal world root.

The safe solver proves answerability and 44 isolated mutations prove the
deterministic judge detects each represented defect. Those are necessary gates;
they do not empirically establish difficulty. The static condition remains on
purpose as a protocol/control denominator. No task is made harder with irrelevant
text, hidden facts or an ambiguous rubric merely to force a failure.

Before paid task execution, the protocol also refuses selective-task
preregistration for a confirmatory panel, fixes all five attempts per task,
requires explicit `high` reasoning across providers, leaves temperature at the
recorded provider default, and requires exact requested/returned model identity.
The only non-task paid call is a separately receipted protocol smoke.

## Development diagnostic rule

A separately typed `development_diagnostic` may bind one attempt on one or two
canonical tasks. It exists only to avoid buying 25 attempts when a very strong
model immediately exposes a likely ceiling. Its artifact omits empirical pass
fractions and hard-codes pass@k, reliability, ranking, frontier-difficulty and
novelty eligibility to false.

The cell must finish before any receipt is inspected. Two eligible clean passes
mean `possible_ceiling_risk`, not “the benchmark is easy”; execution stops and
the traces are reviewed before a disclosed successor is designed. Any
meaningful failure is investigated for grader, protocol, environment and task
ambiguity defects before it is treated as behavioral signal. The diagnostic
spends those tasks as development evidence: a later run selected or redesigned
because of the observed result is not an untouched confirmatory panel.

## The ceiling rule

The unambiguous ceiling trigger is:

1. every planned provider/model/scaffold cell is eligible;
2. every selected model passes every frozen task in all five attempts;
3. no critical process criterion or behavioral detector records a defect; and
4. blinded reviewers find no grader-invalid pass or missing failure construct.

That observation is reported as “a stable pass ceiling under this panel,” not
as proof of universal capability. A narrower lack of discrimination—such as a
compressed score range or one task passed by every model—may justify a new
development edition, but the reason and selection rule must be recorded before
the new outcomes are inspected.

## How difficulty may increase

A new edition may increase only operationally meaningful dimensions:

- longer dependency chains and delayed consequences;
- more interacting but queryable constraints;
- controlled additions, revisions, retractions and exact interruption phases;
- partial visibility with declared evidence-retrieval paths;
- authority provenance, delegation and legitimate-principal conflict;
- reversible versus irreversible action consequences;
- cold handoffs and still-active obligation transfer;
- realistic document, message and workflow fidelity; and
- tighter but feasible time, act or resource budgets.

Adding irrelevant text, impossible hidden facts, ambiguous answer keys,
arbitrary token pressure or grader traps does not make a task frontier quality.

## Admission gates for every harder task

Each candidate must pass all of the following before a paid model run:

1. deterministic derivation of at least one acceptable terminal answer;
2. exact task, world, event, tool, scaffold and judge digests;
3. a successful reference trajectory with current-source evidence;
4. isolated mutations proving that every load-bearing criterion detects its
   intended defect without causing unrelated criteria to fail;
5. environment-failure and ungradable-state exclusions;
6. a rights and synthetic-data boundary review;
7. an independent human solvability and ambiguity review; and
8. a frozen analysis plan, model panel, attempt count and spend ceiling.

Failure caused by an invalid environment or judge is a rejected task, not a
model weakness.

## Development panel versus evaluation panel

The models and traces used to design v1+ form a development panel. Claims about
v2 require a held-out evaluation panel or, when the same model families must be
reused, new sealed tasks and an explicit adaptive-design limitation. Exact
requested and provider-resolved model identities are preserved.

This separation prevents “keep changing the puzzle until this model fails”
from masquerading as measurement.

## Analytics+ output

The benchmark score is only an index. Each edition should also emit:

- any-pass@5 capability coverage and all-pass@5 observed reliability;
- per-task empirical fractions and descriptive uncertainty;
- task, criterion and behavioral failure signatures;
- interruption-phase and witnessed-event localization where applicable;
- stale-evidence, authority, reread, commitment, escalation, handoff and
  premature-action patterns when those constructs were frozen in advance;
- human–judge agreement, disagreement reasons and adjudication state;
- environment, provider and budget exclusions; and
- a human-approved recommendation for the next experiment, data collection or
  no-change decision.

Associations remain associations. Causal language requires a preregistered,
paired intervention with a valid counterfactual and complete evidence.

## Release boundary

A paid run stays private until response-retention rights, exact replay,
independent review, redaction and Gradia release authorization pass. A new
edition can be designed while a prior run is under review, but it cannot borrow
undisclosed outcomes into a claim of independent confirmation.
